# 数字贸易合规沙盒与争议保全

管理数字贸易项目的沙盒准入、跨境数据边界、规则版本和争议保全。

## 参与方与事实

主要参与方包括数字贸易企业、自贸区管理人员、法律服务人员、安全评审人员、争议解决人员。领域资料记录以下已经确认的事实：

- 浙江持续推进自贸试验区数据跨境流动改革和新兴领域沙盒监管
- 数字贸易法治议题覆盖人工智能治理、跨境数据流动、数字支付与在线争议解决
- 相关机制将从年度交流升级为常态化研究协作与规则对话

## 业务约束

- 数据用途边界
- 规则版本
- 试运行限额
- 利益回避
- 商业秘密
- 争议证据保全

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/sandbox_context.py` 负责读取和校验这些资料。

## 合规沙盒后端（`src/sandbox/`）

在领域资料之上实现了一套无外部依赖的后端核心，把上述约束落成可执行规则：

| 模块 | 职责 |
| --- | --- |
| `models.py` | 项目、十类分阶段材料、人员与审查职责、批准边界、评审意见、运行事件、风险、停机记录、争议证据快照 |
| `store.py` | 内存仓储、事务（异常整体回滚）、规则版本、商业秘密授权名单、哈希链操作记录 |
| `clock.py` | 可暂停的业务时钟；服务中断区间不计入整改期限 |
| `services.py` | 准入、评审回避、秘密授权、四条运行处置路径、争议冻结与裁决、停机恢复、主管视图 |
| `errors.py` | 面向业务人员的错误类型 |

### 关键机制

1. **分阶段补材料，批准必须带明确边界**：十类材料（参与主体、数据类别与来源、处理目的、目的地、法律依据、风险评估、合同承诺、技术控制、测试指标、规则知悉）可逐次补交；材料不齐不得申请。作出准入批准时必须明确允许的数据范围、持续时间、用户规模、监测指标和退出条件，并钉住当时的规则版本与各材料版本号。
2. **利益回避与商业秘密最小知悉**：曾参与项目辅导、与申请方有利益关系或本身就是申请方的人员不能被指派评审，也不能提交例外意见；商业秘密材料只向承担对应审查职责（个人信息、地理信息、算法、跨境出境、支付、安全）且获专项授权的人员开放，授权与撤销全部留痕。
3. **四条运行处置路径，原批准决定永久保留**：用途扩张→缩限（只能在原边界内收敛）；指标超限→限期整改（系统登记实测值并自动设定期限）；安全事件→暂停（记住暂停前所处阶段，解除时回到该阶段）；合作方退出或退出条件成就→提前/期满退出。缩限、整改、暂停、退出都不修改原批准决定。
4. **退出生效与容量释放同一事务**：名额占用在批准事务内完成；退出时状态变更、名额释放与操作记录同一事务提交，任一步失败整体回滚，杜绝旧项目仍在运行时把名额分给新申请。
5. **规则更新只影响尚未作出的决定**：每份批准记录其规则版本；新版本生效后，在运项目继续按钉住版本执行，新申请按新版本评审，企业规则知悉版本不一致将被拦截。
6. **争议提出即固定证据**：同一事务内深拷贝当时的材料集合（各版本与密级）、完整访问名单（含已撤销授权）和截至当时的哈希链操作记录。未决争议期间材料封存禁止改动；调解、仲裁或诉讼裁决后按恢复、调整（另存边界修订，原决定不动）、维持退出或维持现状处理。
7. **服务中断跨期限顺延并留证**：业务时钟在中断期间冻结，恢复后受影响的整改期限按停顿时长顺延，中断起止与受影响期限逐项目记录；恢复后仍按原计划推进。
8. **主管视图**：打开项目即可看到获准（或裁决修订后的有效）边界、真实运行阶段、整改期限、未解除风险、在途争议与停机证据。

操作记录采用逐条哈希链（`store.verify_log_chain()` 可复核），所有写操作均在事务内执行。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
